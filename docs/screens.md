# 画面仕様

GUIは4タブ構成。共通事項:

- 保存ボタンはない。全ての入力・編集は即座にDB（`.pschedule`）へ書き込まれる
  （write-through方式）。
- 参照系（ワークフロー・チーム・マイルストーン・タスク等）はすべてドロップダウン
  で選択する。IDを手入力する箇所は一切ない。
- 数値はスピンボックス、日付はカレンダーポップアップ付きの日付編集で入力し、
  不正な値をそもそも入力できないようにする。

## タブ1: 基本情報設定（`gui/tab_basic_info.py`）

プロジェクト全体に関わる基礎データをまとめて1画面で入力する。上から順に:

### プロジェクト概要

- プロジェクト名（自由入力テキスト）
- 開発開始日（カレンダー選択、`QDateEdit`）

いずれも編集完了時（フォーカスが外れた時／日付選択時）に即座に保存する。

### マイルストーン

表形式（列: マイルストーン名／締切日）。

- 「＋追加」: 既定名「新しいマイルストーン」（名前が衝突する場合は自動的に
  「新しいマイルストーン (2)」のように連番を付与し、追加のたびにエラー
  ダイアログが出ないようにする）で1行追加する。追加直後にセルを直接編集して
  名前・日付を変更する。
- 名前セルの直接編集、締切日セルの日付ピッカーは、いずれも変更時に即座に
  DBへ反映される。
- 「－削除」: 選択中の行を削除する。ジョブやタスク上書きから参照されている
  場合は件数を示して確認ダイアログを出す（削除は可能。参照は解除される）。

### チーム

表形式（列: チーム名／同時ライン数）。

- 「＋追加」: 既定名「新しいチーム」（衝突時は連番付与）、ライン数1で追加。
- 同時ライン数はスピンボックス（1〜999）。
- チーム名・ライン数の変更は即座に反映され、ワークフロー設計タブのタスク
  ノード編集ダイアログのチーム候補にも反映される。
- 「－削除」: タスクや上書きから参照されている場合は**削除不可**（ハード
  ブロック）。参照件数を示すダイアログを出して中止する。

### 休業日

表形式（列: 日付／対象チーム）。

- 「＋追加」: 今日の日付・全社共通（対象チーム未設定）で1行追加する。既に
  同日・全社共通の休業日がある場合は、空いている日付を自動的に探して追加する
  （連打してもエラーダイアログが出ないようにするため）。
- 対象チームはドロップダウン（「（全社共通）」＋チーム一覧）。
- 日付・対象チームの変更は即座に反映される。同じ日付・同じ対象（チームまたは
  全社共通）の組み合わせが既に存在する場合はエラーダイアログを出し、変更前の
  状態に戻す。
- 「－削除」: 参照整合性の制約はないため、確認なしで即削除する。

## タブ2: ワークフロー設計（`gui/tab_workflows.py` + `gui/node_canvas.py`）

左右2ペイン構成。

### 左ペイン: ワークフロー一覧

- 「＋追加」: ワークフロー名を尋ねるダイアログを出し、新規ワークフローを作成する。
- 「名前変更」: 選択中のワークフロー名を変更する。
- 「－削除」: このワークフローを使うジョブが1件でもあれば**削除不可**（参照件数を
  示すダイアログを出す）。ジョブが無ければ削除でき、配下のタスク・依存関係も
  連鎖削除される。
- 一覧から選択すると、右ペインにそのワークフローのノードグラフが表示される。

### 右ペイン: ノードグラフキャンバス

タスクを矩形ノードとして配置し、タスク間の依存関係（Internal_Depends）を
ノード間の矢印として視覚的に編集する。

- **タスクの追加**: キャンバスの何もない場所を右クリック→「タスクを追加...」。
  タスク名・担当チーム（ドロップダウン）・所要日数（スピンボックス）を入力する
  ダイアログが開く。チームが1件も無い場合は、チームコンボの末尾「＋ 新しい
  チームを追加...」からその場でチームを新規作成できる（基本情報設定タブに
  移動する必要がない）。
- **タスクの編集**: ノードを右クリック→「編集...」で同じダイアログを開く。
- **タスクの削除**: ノードを選択してDeleteキー、または右クリック→「削除」。
  ジョブ側の上書き・依存関係から参照されていれば件数を示して確認する。
- **タスクの移動**: ノードをドラッグして自由に配置できる。移動後の座標は
  マウスを離した時点でDBへ保存され、次回開いたときも同じレイアウトで表示される。
- **依存関係の作成**: ノード右端の丸（出力アンカー）から、別ノード左端の丸
  （入力アンカー、またはノード本体）へドラッグすると、矢印で依存関係
  （ドラッグ元が先に完了すべきタスク→ドラッグ先が後続タスク）を作成する。
  作成の瞬間に循環依存になるかどうかをBFSで判定し、循環になる場合は
  エラーダイアログを出して追加を拒否する（直接的な循環・間接的な循環の
  いずれも検出する）。
- **依存関係の削除**: 矢印（エッジ）を選択してDeleteキー、または選択して
  右クリックの操作は現状未対応（ノード選択→Deleteのみ）。
- チームマスタ（基本情報設定タブ）で名前や色順が変わった場合、表示中の
  キャンバスは自動的に色・ラベルを更新する。
- 新規ワークフローや、既存Excelから移行したワークフロー（`scripts/
  migrate_excel_to_db.py`）は、依存の深さに基づく簡易レイアウト
  （`gui/node_canvas.py` の `compute_auto_layout`）で初期配置される
  （先行タスクほど左、後続タスクほど右）。

## タブ3: ジョブ（`gui/tab_jobs.py`）

上下2段構成。

### 上段: ジョブ一覧

表形式（列: ジョブ名／ワークフロー／既定マイルストーン／優先度）。

- 「＋追加」: ワークフローが1件も無い場合は追加をブロックし、先に
  「ワークフロー設計」タブでの作成を促す。既定名「新しいジョブ」（連番衝突
  回避付き）・最初のワークフロー・マイルストーン未設定・優先度100で追加する。
- ワークフロー／既定マイルストーンはドロップダウン（マイルストーンは
  「（未設定）」を選べる）。優先度はスピンボックス（1〜999、小さいほど
  高優先）。
- 「－削除」: 他ジョブの外部依存から参照されていれば件数を示して確認する
  （削除すると、それらの外部依存も削除される）。

### 下段: タスク上書き（選択中のジョブ）

上段でジョブを選択すると、そのジョブが使うワークフローの全タスクを自動的に
一覧表示する（手入力不要）。列: タスク名／既定チーム／既定日数（以上3列は
表示専用）／有効／日数上書き／マイルストーン上書き／チーム上書き。

- 「有効」のチェックを外すと、そのジョブではこのタスクを実行しない
  （Job_Tasks の Is_Active=N 相当）。
- 「日数上書き」はスピンボックス（0＝既定日数をそのまま使う、1以上を
  入力するとその日数で上書き）。
- 「マイルストーン上書き」「チーム上書き」はドロップダウン
  （「（既定を使用）」＝上書きしない）。
- 全項目が既定値（有効・日数上書きなし・マイルストーン上書きなし・
  チーム上書きなし）に戻ると、DB上の上書き行は自動的に削除される
  （差分のみ保持する設計、詳細は `docs/db_design.md`）。

## タブ4: 依存関係（`gui/tab_dependencies.py`）

ジョブをまたぐタスク依存（External_Dependencies相当）の一覧・追加・削除。

- 表は表示専用（列: 依存するジョブ／タスク／依存先ジョブ／依存先タスク）。
  既存行をその場で編集することはできない（削除して作り直す）。
- 「＋追加」: ジョブが1件も無い場合はブロックし、先に「ジョブ」タブでの
  作成を促す。ジョブが存在すればダイアログを開き、「依存するジョブ→
  タスク」「依存先ジョブ→タスク」をそれぞれカスケードするドロップダウンで
  選択する（ジョブを選ぶと、そのジョブが使うワークフローのタスク一覧に
  タスクの選択肢が絞り込まれる）。自己依存やIDの手入力は発生しない。
- 「－削除」: 選択中の行を確認なしで削除する。
- ジョブをまたぐ依存が循環している場合は、この画面では検出せず、ガント
  チャート生成時（タブ横断の処理）に `CircularDependencyError` として
  検出・表示する（詳細は `docs/architecture.md`）。
