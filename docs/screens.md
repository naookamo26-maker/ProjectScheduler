# 画面仕様

GUIは4タブ構成。共通事項:

- 保存ボタンはない。全ての入力・編集は即座にDB（`.pschedule`）へ書き込まれる
  （write-through方式）。
- 参照系（ワークフロー・チーム・マイルストーン・タスク等）はすべてドロップダウン
  で選択する。IDを手入力する箇所は一切ない。
- 数値はスピンボックス、日付はカレンダーポップアップ付きの日付編集で入力し、
  不正な値をそもそも入力できないようにする。

## タブ1: 基本情報設定（`gui/tab_basic_info.py`）

プロジェクト全体に関わる基礎データをまとめて1画面で入力する。上から順に:

### プロジェクト概要

- プロジェクト名（自由入力テキスト）
- 開発開始日（カレンダー選択、`QDateEdit`）

いずれも編集完了時（フォーカスが外れた時／日付選択時）に即座に保存する。

### マイルストーン

表形式（列: マイルストーン名／締切日）。

- 「＋追加」: 既定名「新しいマイルストーン」（名前が衝突する場合は自動的に
  「新しいマイルストーン (2)」のように連番を付与し、追加のたびにエラー
  ダイアログが出ないようにする）で1行追加する。追加直後にセルを直接編集して
  名前・日付を変更する。
- 名前セルの直接編集、締切日セルの日付ピッカーは、いずれも変更時に即座に
  DBへ反映される。
- 「－削除」: 選択中の行を削除する。ジョブやタスク上書きから参照されている
  場合は件数を示して確認ダイアログを出す（削除は可能。参照は解除される）。

### チーム

表形式（列: チーム名／同時ライン数）。

- 「＋追加」: 既定名「新しいチーム」（衝突時は連番付与）、ライン数1で追加。
- 同時ライン数はスピンボックス（1〜999）。
- チーム名・ライン数の変更は即座に反映され、ワークフロー設計タブのタスク
  ノード編集ダイアログのチーム候補にも反映される。
- 「－削除」: タスクや上書きから参照されている場合は**削除不可**（ハード
  ブロック）。参照件数を示すダイアログを出して中止する。

### 休業日

表形式（列: 日付／対象チーム）。

- 「＋追加」: 今日の日付・全社共通（対象チーム未設定）で1行追加する。既に
  同日・全社共通の休業日がある場合は、空いている日付を自動的に探して追加する
  （連打してもエラーダイアログが出ないようにするため）。
- 対象チームはドロップダウン（「（全社共通）」＋チーム一覧）。
- 日付・対象チームの変更は即座に反映される。同じ日付・同じ対象（チームまたは
  全社共通）の組み合わせが既に存在する場合はエラーダイアログを出し、変更前の
  状態に戻す。
- 「－削除」: 参照整合性の制約はないため、確認なしで即削除する。
