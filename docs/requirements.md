# 要件定義

## 背景・目的

`project_scheduler.py`（リソース制約付きプロジェクトスケジューラー）の入力は、
Project/Milestones/Teams/Workflows/Jobs/Job_Tasks/Holidays/
External_Dependencies という多シート構成のExcelを手編集する方式だった。
シート間はID（`Workflow_ID`、`Team_ID`、`Job_ID:Task_ID` 等）で相互参照して
おり、手入力ではタイプミス・参照ミスが起きやすく、依存関係（特にジョブを
またぐ外部依存）の全体像も文字列の羅列からは把握しづらい。

これを解消するため、PySide6製のデスクトップGUIを新設し、入力データの作成を
「名前をドロップダウンで選ぶ」「タスクをキャンバス上で線でつなぐ」といった
直感的な操作に置き換える。IDはユーザーに一切意識させず、内部的にのみ管理する。

## 機能要件

### 4タブ構成

| タブ | 内容 |
|---|---|
| 基本情報設定 | プロジェクト名・開始日・マイルストーン・チームマスタ・休業日 |
| ワークフロー設計 | ワークフロー（タスクテンプレート）とタスク間依存関係をノードグラフで編集 |
| ジョブ | ワークフローを実体化してジョブを作成、優先度・マイルストーン・タスク単位の上書きを設定 |
| 依存関係 | ジョブをまたぐタスク依存（External_Dependencies相当）を専用画面で管理 |

各タブの詳細な画面仕様は `docs/screens.md` を参照。

### 主要な機能

- **ノードグラフによる依存関係編集**: ワークフロー内のタスクを矩形ノードとして
  配置し、ドラッグで依存の矢印を作成する。循環依存になる操作は作成時点で
  検出・拒否する。
- **ガントチャート生成**: DBの内容から直接（Excelファイルを経由せず）
  `project_scheduler.py` のスケジューリングエンジンを呼び出し、Mermaid
  Markdown・インタラクティブHTMLの2形式でガントチャートを出力する。
- **サンプルデータのDB化**: 既存のExcelサンプル
  （`data/Project_Schedule_Sample_GameDev_v22.xlsx`）を一度きりの移行
  スクリプト（`scripts/migrate_excel_to_db.py`）でDB形式に変換し、GUIで
  すぐに開いて試せるようにする。
- **Windows向け配布**: PyInstallerによる `.exe` パッケージング
  （GitHub Actionsでの自動ビルドに対応）。

## 非機能要件

- **IDを一切表示しない**: 画面上のあらゆる参照（チーム・ワークフロー・
  マイルストーン・タスク・ジョブ）はドロップダウン等の名前ベースの選択で
  行い、生のID・連番を表示しない。
- **ミスの構造的防止**: 数値はスピンボックス、日付はカレンダー選択で不正な
  値を入力できないようにする。名前の重複や、参照が残っている行の削除は
  分かりやすいダイアログでブロック/警告する。
- **保存操作を意識させない**: 明示的な「保存」ボタンは持たず、編集の都度
  即座にDB（`.pschedule`）へ書き込む（write-through方式）。
- **サーバー不要**: GUI・出力（ガントチャートHTML）ともにローカル完結で
  動作する（既存のHTMLガントチャート出力機能を踏襲）。

## 主要な意思決定（ヒアリングで確定した経緯）

開発の過程で複数回のヒアリングを行い、以下を確定させた:

1. **保存形式はSQLite、1プロジェクト＝1ファイル**。Excelへの書き出しは
   行わない。DBの内容から直接 `project_scheduler.py` を呼び出す。
   拡張子は汎用的な `.db` ではなく、このツール専用の `.pschedule` にする
   （実体は標準SQLiteファイルのまま、識別しやすくするための命名）。
2. **依存関係の編集はノードグラフ**（テーブル＋ドロップダウンではなく、
   キャンバス上でタスクを線でつなぐグラフィカルな操作）を採用する。
   ワークフロー設計タブに限定したガントチャート風プレビューは、チーム・
   優先度・マイルストーンがまだ確定していない段階では意味を持ちにくいため
   作らない（ノードグラフ自体が依存関係の可視化を兼ねる）。
3. **チーム・休業日はプロジェクト概要タブに統合**し、「基本情報設定」
   タブとする（当初案では独立タブだったが、他のマスタ情報と合わせて
   1画面で完結させる方が使いやすいと判断）。
4. **`project_scheduler.py` は内部改変も許容する**。当初は「取り込むが
   中身は変更しない」方針だったが、Excelバッファを経由する設計は無駄が
   あるため、DataFrameを直接受け取る新しい入口
   （`run_resource_constrained_scheduler_from_frames`）を追加する形で
   リファクタリングした（詳細は `docs/architecture.md`）。
5. **既存のExcelサンプルはDB形式に変換**し、GUIですぐ試せるようにする
   （常設のインポート機能ではなく、一度きりの移行スクリプトとして提供）。
6. **配布はWindows向け `.exe`**。ビルド環境の制約（PyInstallerはクロス
   コンパイル非対応）から、GitHub Actionsでの自動ビルドを整備する
   （詳細は `docs/packaging.md`）。

## 対象外（スコープ外）

- Excelファイルへの書き出し機能（意図的に廃止）
- GUIでの既存Excelの継続的なインポート機能（一度きりの移行スクリプトのみ提供）
- 複数プロジェクトを1つのDBファイルで切り替える機能（1プロジェクト＝1ファイル）
- pytest-qt等によるウィジェット層の自動テスト（開発時にheadless Qtで手動検証）
