## プロジェクト

計画全体の単位です。1つのプロジェクトは1つのファイル（拡張子 `.pschedule`）に保存します。
プロジェクトには名前と**開発開始日**があり、ツールは開発開始日より前には作業を置きません。

## マイルストーン

**締切**を表します。「試作完了」「発売」のように名前と締切日を持ちます。

ジョブ（後述）ごとに「どのマイルストーンまでに終えるか」を決めます。
同じジョブの中でも、一部のタスクだけ別のマイルストーンに合わせることもできます
（サンプルでは、各モジュールの「要件定義」だけを「企画承認」までに終える設定にしています）。

締切に間に合わない作業があっても、ツールは計画の作成を止めません。
間に合わない作業を目立つ表示で示し、何日遅れるかを知らせます。

## チームとライン数

**チーム**は、作業を受け持つ単位です。部署でも、個人でも、協力会社でも構いません。
すべてのタスクは、いずれかのチームが受け持ちます。

**ライン数**は、そのチームが**同時に並行して進められる作業の本数**です。
ツールは、各チームの作業がライン数を超えて重ならないように日程を組みます。
ライン数は次の3通りで指定します。

| 指定 | 意味 |
| --- | --- |
| 指定なし | 上限を設けません（新しく作ったチームの既定）。何本でも同時に進められるものとして日程を組みます |
| 0 | その期間は作業をしません（途中から加わる、途中で抜けるチームを表せます） |
| 1以上 | その本数まで同時に進められます |

ライン数は期間の途中で変えられます（**変動点**）。
サンプルの「製造」チームは、工場が立ち上がるまで 0、立ち上がった後は 2 にしています。

!!! kikan-note "ライン数は人数ではありません"
    ライン数は「同時にいくつの作業を並行して進められるか」を表します。
    3人のチームでも、3人で1つの作業に取り組むならライン数は 1 です。
    人数や工数の配分は、このツールでは扱いません。

「指定なし」のまま日程を組むと、各チームが**同時にいくつの作業を抱える計画になるか**が分かります
（「プロジェクト分析」の章で確かめ方を説明します）。
そこから「これだけの本数は並行できない」というチームにだけ、上限を設定していく使い方もできます。

## 休業日と営業日

土曜・日曜と日本の祝日は、自動的に作業をしない日として扱います。
これに加えて、年末年始や夏季休業などの**休業日**を登録できます。
休業日は、全チーム共通にも、特定のチームだけにも設定できます。

作業をする日（休業日を除いた日）を**営業日**と呼びます。
このツールの日数は、すべて営業日で数えます。

## ワークフローとタスク

**ワークフロー**は、**作業の流れの型**です。
「製品モジュール開発」「販売準備」のように、繰り返し現れる仕事の進め方を1回だけ作っておきます。

ワークフローの中の1つ1つの作業を**タスク**と呼びます。
タスクには、既定の担当チームと**日数**を決めます。

!!! kikan-note "タスクの日数は「期間」です"
    タスクの日数は、**着手してから完了するまでにかかる期間**（営業日）です。
    「25日」は「着手から25営業日で仕上がる」という意味で、「25人日の作業量」ではありません。
    何人で取り組むかではなく、「どれくらいの期間で仕上がるか」で決めてください。

## 依存

**依存**は、タスクの前後関係です。
「基本設計が終わったら詳細設計を始める」のように、先に終わるべきタスク（**先行タスク**）と、
その後に始めるタスク（**後続タスク**）を矢印でつなぎます。

1つのタスクが複数の先行タスクを待つこともできます。
上の画面では、「試作」は「詳細設計」と「部品調達」の両方が終わるのを待ちます。

既定は「先行タスクが終わったら始める」ですが、「先行タスクと同時に始める」ことや、
間を何日か空けることもできます（「ワークフロー設計」の節で説明します）。

## ジョブ

**ジョブ**は、ワークフローの型から作る**実際の仕事**です。
「製品モジュール開発」という型から、「本体」「制御基板」「筐体」…のようにジョブを作ると、
それぞれのジョブが型と同じタスクと依存を持ちます。

ジョブごとに次のことを決めます。

- どのワークフローから作るか
- どのマイルストーンまでに終えるか（既定マイルストーン）
- 優先度（後述）
- タグ（「国内」「海外」など、絞り込みに使う自由な目印）

型のままでは合わない部分は、そのジョブだけ**上書き**できます。
例えば「付属品は既製品を使うので部品調達は10日」「このジョブでは操作手順書を作らない」
といった調整です。型を変えずに済むので、同じ型のジョブを何件でも作れます。

## ジョブ同士の依存

別のジョブの作業を待つこともあります。
サンプルでは、「第1工場」（量産準備）の工程設計は、「本体」（製品モジュール開発）の詳細設計が
終わるのを待ちます。

このようなジョブ同士の依存は、ジョブを選んで「このジョブを待つ」と指定するだけで設定できます。
どのタスクがどのタスクを待つかは、ワークフローの組み合わせごとに**依存テンプレート**として
一度決めておけば、ツールが自動で当てはめます。

## 優先度

複数の作業が同じチームのラインを取り合ったとき、どれを先に進めるかを決める数値です。
**数値が小さいほど優先**されます。指定しないジョブは、最も後回しになります。

## あなたが決めること、ツールが決めること

このツールでは、入力と結果がはっきり分かれています。

| あなたが決めること | ツールが決めること |
| --- | --- |
| 作業の流れ（ワークフロー・タスク・依存） | 各タスクの開始日と終了日 |
| 各タスクの担当チームと日数（期間） | チームのラインを超えないような作業の順番 |
| チームのライン数と休業日 | 締切に間に合わない作業と、その遅れの日数 |
| ジョブ、締切（マイルストーン）、優先度 | |

日程を思いどおりにしたいときは、日程そのものではなく**左側の条件を見直します**。
例えば、締切に間に合わない作業が出たら、優先度・ライン数・日数・依存・締切のどれを変えるかを検討します。
条件を変えると、ツールがすぐに日程を組み直します。

ただし、「この作業はこの日に始める」と決まっているものは、日付を固定することもできます
（**開始固定日**。「ジョブ作成」の節で説明します）。
