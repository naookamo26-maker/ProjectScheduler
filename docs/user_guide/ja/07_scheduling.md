# 日程の決まり方

ツールがどんな決まりで日程を組み立てるかを説明します。
思ったとおりの日程にならないときは、この章の決まりに照らして、どの条件を変えればよいかを考えてください。

## 基本の決まり

ツールは、次の決まりをすべて守るように、各タスクの開始日と終了日を決めます。

| 決まり | 内容 |
| --- | --- |
| 開発開始日 | 開発開始日より前には、どのタスクも置きません |
| 依存 | 先行タスクが終わってから、後続タスクを始めます（依存の種類やラグを設定していれば、それに従います） |
| ライン数 | 各チームが同時に進めるタスクの数は、そのチームのライン数を超えません |
| 休み | 土日・祝日・休業日には作業しません |
| 開始固定日 | 開始固定日を設定したタスクは、ほかの決まりより優先して、その日に始めます（下記） |
| 確定した日程 | 計画を確定しているときは、確定した日程を守ります（「計画の確定と再計画」の章） |

同じ入力からは、いつ計算しても同じ日程が組み立てられます。
ファイルを開き直しただけで日程が変わることはありません。

## 日数は営業日で数えます

タスクの日数は、作業をする日（**営業日**）だけで数えます。
土日・祝日・休業日は数えません。チームだけの休業日は、そのチームのタスクにだけ効きます。

そのため、ガントチャートのバーは、休みをまたぐと日数より長く見えます。
例えば、下の「配置」の節の 100% の図では、3日の「仕様作成」が土日をまたいでいるため、バーは5日分の長さです。
また、「仕様作成」と「アート制作」の間の1日の空きは、祝日（11/3 文化の日）です。

!!! kikan-note "日数は営業日で数える「期間」です"
    「5日」は「着手から5営業日で仕上がる」という意味です。作業量（工数）ではありません。

## 作業がぶつかったとき（優先度）

同じチームのタスクが同じ時期に重なり、ライン数を超えてしまうときは、**優先度の高いジョブのタスクが先に**その時期を取ります。
優先度の低いジョブのタスクは、ラインが空くまで後ろにずれます。

先にしたいジョブがあるときは、優先度に差を付けてください。

## 配置

ガントチャートタブの右上にある**配置**で、タスクを「いつ始めるか」の基準を決めます。

- **最速（0%）**: 始められるようになったら、すぐに始めます。
- **ギリギリ（100%）**: 締切に間に合う範囲で、できるだけ遅く始めます。
- その間の値: 最速とギリギリの間の、その割合の位置を基準にします。既定は 70% です。

どの値でも、**締切に間に合う置き方があれば、必ず間に合うように置きます**。
基準の位置でチームの手が空いていなければ、間に合う範囲で前後の空いている時期を探します。

使い分けの例:

- **最速**: 全体がいちばん早くていつ終わるか、締切までにどれだけ余裕があるかを見たいとき。
- **70%前後**: 作業が特定の時期に偏らないように、期間全体に広げて置きたいとき。
- **ギリギリ**: 各タスクを、遅くともいつまでに始めなければならないかを見たいとき。

「配置」の値はプロジェクトファイルに保存されます。

## 締切に間に合わないとき

ライン数が足りない、依存の流れが長すぎる、などの理由で締切に間に合う置き方が無いタスクは、
**できるだけ早い日程に置いたうえで**、赤い太枠で表示し、何日遅れるかを知らせます。

間に合わせるには、次のような条件の見直しを検討します。

| 見直すこと | 効き方 |
| --- | --- |
| 優先度 | 間に合わせたいジョブの優先度を上げると、そのジョブが先に時期を取ります（代わりにほかのジョブが後ろにずれることがあります） |
| ライン数 | 混み合っているチームのライン数を増やすと、同時に進められる作業が増えます |
| 日数 | タスクの期間を見直します |
| 依存 | 本当に待つ必要がある依存かを見直します。「開始 → 開始」やマイナスのラグで、前の作業と重ねて始められることもあります |
| 締切 | マイルストーンの締切や、ジョブ・タスクがどの締切に属するかを見直します |

プロジェクト分析タブの「チーム」で、どのチームが混み合っているか（上限に張り付いた日数、押し出された件数）を確かめると、見直す場所の見当がつきます。

## 開始固定日が矛盾しているとき

開始固定日を設定したタスクは、ほかのタスクより先に、固定した日を確保します。
固定した日が次のような無理のある日付でも、**固定した日のまま置き**、オレンジの破線の枠で知らせます。

- 先行タスクが終わる前の日付に固定した
- 同じ時期に固定したタスクが重なり、チームのライン数を超えた

上部の赤字とバーにマウスを乗せたときの説明で、どう矛盾しているか（例えば「依存タスクの着手可能日より2日早い」）が分かります。
固定した日付が本当に正しいか、先行タスクの日程を早められないか、ライン数が足りているかを見直してください。
